## 會議紀錄

### 一、開場說明內容

**1. 研究範圍:聚焦投資行為**

- 先聚焦在投資行為,觀察哪些行為可以被重複,以及哪些特徵會反映在哪類產品上,不一次擴散到太大範圍。
- 範疇限定在行為財務的投資行為內。

**2. 如何驗證:不限定方法,由學生發揮**

- 不限定模型、流程或實驗設計。這是學生賽,希望看到創意與方法論。
- 評審重點是嚴謹度,以及論證如何支撐最終結論。評分標準由教授或學會另行說明。
- 銀行過去的做法是直接統計 outcome(例如買入=1、賣出=2),再算 PnL 等結果。這種做法統計上單純,但無法證明客戶背景與參數真的影響了 outcome。
- **銀行代表的核心建議:多加一個「推理脈絡」欄位**
    - 要求 LLM 在給出 outcome(1~4 其中之一)時,同時忠實、詳細說明參考了什麼、如何思考才得出這個答案。
    - 目的:驗證 outcome 是否真的來自設定的客戶背景與事件,還是在該背景下平均而言最可能給的答案(等同隨機)。
    - 同一欄位也能回答「有沒有參考歷史經驗,還是只依當下事件作答」,可要求 LLM 說明是基於怎樣的經驗與歷史。
    - 這是個人建議,不是硬性規定。

**3. AI 代理人的模型使用規範**

- 不限定模型或品牌。銀行不提供 API 與算力。
- 建議使用閉源模型。銀行實務上也都用閉源模型,沒有把開源模型部署在自家地端算力上。
- 資料面向:大部分已提供「去識別化」的資料類別。

**4. 客群人設與風險屬性**

- 不偏好、不限制人設設定。唯一共同標準:以台灣的樣態為主。
- 人設設多細、放哪些參數、風險屬性怎麼分,銀行尊重學生設計。
- 因為是學術競賽,必須能明確說明人設與風險屬性最終影響範圍多大、權重多重。這要在實驗設計一開始就想好,並規劃如何納入分析。

**5. 累積實驗與記憶情境設計**

- 呼應前面的建議:記憶與歷史經驗要納入實驗設計。

**6. 銀行未來如何運用成果**

- 找出關鍵參數:描述客戶時哪些參數必須放、哪些不能放、哪些會顯著影響 outcome。
- 找出 LLM 的盲區:不論人設怎麼設定,LLM 回答都高度相近的部分,代表這些面向無法靠 LLM 取得有區別力的回覆。
- 加速產品與服務優化:快速知道 LLM 建議可信賴到什麼程度,加快產品服務推出速度與客戶前期準備作業。

### 二、問答與討論

**Q:AI 虛擬客戶用於上線前測試,銀行比較怕假陰性還是假陽性?**

- 銀行代表:比較怕的是「實際應為否,卻判斷為是」,也就是客戶沒有需求或意願,卻被判斷成有需求。
- 原因:會過度打擾客戶,客戶會覺得「第一次接觸就這麼不了解我」,後續建議也聽不進去。
- 相對地,漏掉有需求的客戶,後續仍有機會再接觸、再發掘需求,代價較小。
- 另有「強度」差別:是強烈認定客戶有需求,或只是用較柔性的方式試探,兩者影響不同。

**Q:模型是否一定要用閉源?**

- 銀行目前使用的多為閉源模型(例如 Azure 上的 OpenAI 模型、Claude),國內銀行沒有能力買足夠 GPU 在地端跑開源模型,且要處理的資料量大。
- 不反對使用開源或其他模型:銀行重視的是實驗設計、如何控制變數、如何推導並陳述變數對 outcome 的影響。有算力可以用,不反對。
- 個資合規:銀行給閉源模型使用的資料一定會先做去識別化處理,因此不認為有此方面的限制。

**Q:成果期待偏實務與銀行政策連結,還是研究嚴謹性?**

- 銀行代表:這次競賽與研究機構合作,**更看重嚴謹性**。
- 理由:過去兩個案例(見下)答不出「哪些參數影響了哪些 outcome」,就是因為缺乏根本的方法論驗證,不知道在 agent 設計上哪些參數有顯著影響,哪些回答只是一次性、不具參考性。有嚴謹的基礎,後續應用才有把握。
- 請學會與教授補充。

**謝志昇副理事長的意見**

- 永豐的題目是探討 LLM 能否協助銀行預測或了解客戶反應,與行為財務相當切合。這個方向還很新,已發表的期刊文獻有限。
- **文獻建議**:多看行為財務相關的研討會論文,通常可下載,可參考別人用什麼角度與設定。
- **方法建議**:可參考計算社會科學的 agent-based model(代理人基模型);目前也有研究讓 LLM 扮演代理人,與本題相近。
- **書面報告建議**:評審時間很短,最怕寫二三十頁像作文、抓不到重點。
    - 想像成向資金提供者提案,重點放最前面。
    - 建議結構:研究題目 → 摘要(主題、方法、主要發現)→ 約半頁以內條列式的研究重要性與 impact → 之後才是研究源起、方法、文獻等細節。
- 補充一個提醒:行為財務傳統上用真人受試者,設計實驗組與對照組看 treatment effect。這次受試者換成 LLM agent,多了一層複雜性:除了實驗設計本身,還要考慮 agent 的邊界與回答是否像真人。不要只把重心放在模型怎麼設定,仍要回到科學研究本質,要有對照組與實驗組。

**Q:實務應用的真實例子?**

- 銀行代表:銀行已有系統在測試,餵入不同客戶資料,看客戶預期的心理安全帳戶金額與追求的報酬率。
- 延伸到本主題的原因:過去只看 outcome,沒有仔細推敲。至少在這個階段可以驗證:**傳統經典、已被驗證的行為財務理論,LLM 在被賦予角色的情況下能重現到什麼程度。**
- 例如 LLM 本身像 IQ 180,被要求扮演 IQ 90 的人時,真的會降到那個水準回答嗎?這會反映在背景參數的設定上。
- 因此建議多一個欄位敘述分析脈絡:若脈絡明顯不是該人設應有的,就可以檢視出來。

**Q:要針對單一偏誤,還是重現多個行為財務現象?**

- 不限定,回到實驗設計與想驗證的內容,由學生發揮。
- 銀行代表個人看法:不要太貪心,一次重現太多個。一篇約 20 頁的報告若講 10 個偏誤,每個的深度與嚴謹性、邏輯脈絡都會不足;可選 3~4 個有意義的,或 1~2 個。

**Q:是否採用 one-shot prompt(單次提示)的實驗設計?**

- 銀行代表:不建議用 one-shot 的方式。要模擬一個人,應該有歷史累積經驗;今天的決策依據昨天、前天的經驗,不是單次片段。
- 這也是建議加「推理脈絡」的原因:可觀察前面的 outcome 是否影響現在的決策。行為財務中的參考點(基準點)即來自過去經驗或現有部位,因此不會採用 one-shot 設計。

**Q:研究重現資料包是什麼?**

- 謝副理事長:為了讓審查者確認結果不是造假,提供程式碼與所有細節,讓審查者能重現結果。
- 不用另外附在報告頁數內。可存成資料夾壓縮,上傳到指定網站,或存雲端(Google Drive、OneDrive、Dropbox)並在報名系統貼下載連結。報告中可簡短說明資料包內容。
- 學會:目前沒有格式限制,重點是能順利存取下載、不要加密到打不開;放 GitHub 也尊重(銀行代表認為 GitHub 可以直接呈現並重跑流程)。

**Q:AI 使用聲明書要寫什麼?**

- 學會:說明使用了哪些 AI 工具,以及產出內容沒有違反學術倫理規範。
- 謝副理事長:這次題目本來就需要用 AI 生成代理人行為,所以只需說明 AI 使用範疇即可。

**Q:只用公開資料校準 AI 代理人,評審是否視為資料來源充分?可否用已發表文獻統計作基準?**

- 謝副理事長:都可以,是科學且客觀的做法。題目很新,銀行受法規限制也無法提供太多客戶資料,只要根據公開資料設定環境並說明清楚即可。

**Q:用 Python 做台股量化回測,資料範圍與 agent 的角色?**

- 銀行代表:要想清楚 Python 回測在設計中的目的。若是給「技術型投資人」這類角色專屬的回測資料,合理;但若所有角色看同樣的回測結果,目的是什麼要釐清。
- 資料量大不是問題,只有處理得了與否的問題。放進來的參數應是討論後認為重要的;若放 10 個參數有 8 個不重要,這本身就是思考成果。「沒有結果」也有價值:告訴後人這些東西在這次實驗中看不出影響,不必再做。

**銀行過去的兩個案例(補充背景)**

1. **100 位客戶滿意度測試**:約一年前,把 100 位客戶各 10 個欄位資料餵給 LLM,請它評估對某服務流程的滿意度,得到平均 7 分與 3 個建議。被質疑:這 7 分是真的模擬 100 位客戶得出,還是 LLM 訓練參數下「最可能的平均數」?無法提出有效的科學論證。
2. **客戶心理安全帳戶與追求報酬率推論**:給 LLM 客戶背景,一定答得出來,但不知道哪些參數真的重要、哪些真的影響 outcome。
- 傳統做法是做真實客戶訪談或問卷,成本高、工耗大,拉長服務迭代流程;這也是希望用 agent 加速的原因。
- 這兩個案例只是引發提案的發想,不代表一定要靠這次競賽完美回應。

### 三、補充回覆與結語

**銀行代表回覆:研究範圍為何要限縮**

- 以兩個案例來看,無法知道代理客戶回覆中哪些具共同性、哪些沒有參考性。因此研究上先限縮在某個情境或領域,了解 LLM 客戶代理的邊界在哪。
- 是否擴展到行銷、行銷服務等領域,是未來有專業研究基礎後,銀行內部再延伸討論。

**Q:模型一定要用閉源嗎?** 同前述,不限定。

**謝副理事長補充**

- 行為財務平常以真人為受試者並設計實驗組與對照組;這次對象換成 LLM agent,是「兩個維度」的問題:實驗設計,加上 agent 的邊界與回答是否與真人一致。
- 大家都在討論用閉源還是開源模型,卻很少回到研究主軸。仍必須有 treatment effect 的設計,有實驗組與對照組,透過比較才知道設計的機制有什麼用。
- 以銀行推廣財務規劃服務為例:要有接受服務與未接受服務的兩組客戶比較,才知道客戶滿意與否;沒有對照組,研究就失去探討的重點。

**銀行代表回覆:穩定性分析、角色設定有效性、驗證基準**

- **穩定性分析**:實驗設計完成後重新跑一次,是否能重現同樣結果,不是隨機產生。
- **角色(人設)有效性是核心問題**:LLM 參數固定,外界與銀行做了很多人設設定,真的有效嗎?如果不論怎麼設定,回答都差不多,代表 LLM 回答可能只是基於模型本身參數,而非角色背景。
- 銀行內部實驗例子:告訴 LLM「你是健身教練、擅長教游泳」,問財務問題,仍回答得很好。需要觀察:遇到超出角色認知範圍的問題時,LLM 用的是角色的認知還是模型本身的知識?這關係到設定客戶背景參數的有效性。
- **如何判斷有效性**:目前沒有真實客戶案例可用,但已有文獻使用了哪些人、得到什麼效果數值,可作為基準點。可在相同情境與背景下,比較 LLM 的行為反應與文獻是否貼近。銀行代表同意使用文獻的估計值作為實驗參考點。

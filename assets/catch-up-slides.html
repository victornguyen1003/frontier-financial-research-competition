PM page · 14 Nov · Justin

“Regression issue”: the logit must match what Barber measures

  • Barber runs no regression. PGR and PLR are daily hazard rates over positions still held, with the average purchase price as reference.
  • Use a position-day panel (agent × stock × day). Positions leave once sold, so the logit becomes a discrete-time hazard model.
  • Pick one memory definition. If “memory” is the price path, it is collinear with G and dd.
  • Compare ratios and signs, not levels. An LLM that decides every period sells far more often than 3–9% a day.
  • With an interaction term, β2 is the DE for the baseline arm only. Report odds ratios or marginal effects per arm.
  • Barber is probably in the training data, so a result near 2× might be recall.

The prototype found a reverse disposition effect, and memory moves it toward zero

Study 1 v2 full run: 900 runs (3 personas × 3 arms × 100 scenarios), 5 stocks, 15 periods, σ = 10% driftless paths. DE = PGR − PLR, pooled, with 95% bootstrap CI.

How the team read it

  • The direction is the opposite of humans. Possible causes: the model guesses the experiment and behaves “rationally”, or it knows the DE literature.
  • Memory raises DE: reflect − none = +0.16 overall and +0.35 for young_active. That supports Q2 even though the levels are negative.
  • Three personas is too few, and details like “age 27” have no data behind them. The team asked for more personas, based on literature or statistics.
  • Whatever the sign, it is writable: “memory is a key parameter of simulated-investor outcomes.”

Official SinoPac consultation · 25 Nov · the project now follows this

What the bank and the association want

  • rigorRigor over practicality. Past bank pilots couldn't say which parameters drove which outcome.
  • personaPersona validity is the core question. If outputs barely change across personas, the LLM is answering from its own parameters. Plan from the start how to measure each attribute's weight.
  • new fieldAdd a reasoning field: a faithful, detailed account of what the agent used to decide. It shows whether the persona and past experience drove the outcome.
  • designTreatment and control groups. No one-shot prompts: decisions build on accumulated experience.
  • stabilityRerun the design and get the same result.
  • Data: public data and literature estimates such as Barber (2007) are acceptable benchmarks.
  • Models: closed models are suggested but not required.
  • Scope: one or two biases, at most three or four.
  • Null results have value, for example “these 8 of 10 parameters don't matter.”
  • Report format: title, abstract, then half a page of impact bullets. Write it like a pitch to funders.
  • Replication package: a GitHub link is fine.
  • AI-use statement: just describe the scope of AI use.

The bank will use the results to find the key parameters for describing customers, and the LLM's blind spots: aspects where every persona answers the same way.

Notion: 官方線上諮詢會議9
New direction

From “can we reproduce the DE?” to “do persona settings really drive it?”

Research questions

  1. Persona validity. Do the persona parameters we set change trading behaviour (PGR, PLR), or does the LLM act the same whatever the persona?
  2. Key parameters and blind spots. Which parameters move the disposition effect, by how much, and which make no difference?
  3. Accumulated experience. Does memory (trade history, reflection) shape decisions, judged from both outcomes and the reasoning field?
  4. Stability. Do the results hold across reruns and new price paths?

Benchmark: Barber et al. (2007) values as the reference point for direction and size, for example individuals' PGR/PLR ≈ 2.6 and institutions ≈ 0.7–0.9.

Design

  • Control: a neutral persona with no psychology or trait description.
  • Treatments: persona parameters (psychology, traits, demographics) randomized, each run on the same price paths.
  • Memory arms: none / history / reflection, crossed with personas.
  • Upper bound: “you have a DE” as a manipulation check only.
  • Output: order + detailed reasoning. Code whether the reasoning cites the persona or past trades.
  • Estimate: each parameter's effect on PGR − PLR, clustered by path. Rerun for stability.
